# SimpleLift

**SimpleLift by PLAYCITY BLOCK**

[English](README.md)

SimpleLift는 Bukkit 계열 마인크래프트 서버용 승강기 플러그인입니다. 일반 블록만으로 지은 승강로를 따라 플레이어, 몹, 탈것을 층 사이로 옮깁니다. Lift와 LiftReloaded의 설정 키, 명령어 이름, 권한 노드, 표지판 배치를 유지합니다. 호환되는 기존 승강기는 구조 변환이 필요하지 않지만, 운영 적용 전에는 별도 서버 사본에서 확인하십시오.

승강기는 건축물 그 자체입니다. 최하층의 base 블록, 같은 열 위쪽 각 층의 floor 블록, 각 층의 버튼과 그 위 벽 표지판이 승강기를 정의합니다. 승강기 데이터베이스도 등록 명령어도 없습니다. 운행할 때마다 월드에서 구조를 다시 읽으므로 floor 블록을 부수거나 표지판을 옮기면 즉시 반영됩니다.

실질적인 장점은 이 설계에서 나옵니다. 승강기 정의를 별도 목록이 아니라 월드에 두므로 월드 복사나 롤백 때 데이터베이스를 맞출 필요가 없습니다. Lift나 LiftReloaded에서 옮겨올 때도 구조 변환 없이 첫 실행 시 설정 파일만 자동으로 가져옵니다. Java 8 바이트코드 JAR 하나로 Minecraft 1.13부터 26.3까지를 대상으로 합니다.

한 번의 운행은 출발 층에 서 있던 모두를 함께 태우고, 승강기가 지나가는 층에서 기다리는 대상은 제자리에 붙잡아 보호하며, 임시로 치운 블록과 변경한 엔티티 속성을 운행이 끝날 때 모두 되돌립니다.

## 승강기 구조

높이는 층 높이(`floor`)에 놓인 floor 블록을 기준으로 합니다.

```text
floor + 3   벽 표지판 — 제어 표지판
floor + 2   버튼
floor + 1   빈 공간, 또는 층 이름을 적는 선택적 벽 표지판
floor       base 블록(최하층) 또는 floor 블록(그 위 모든 층)
```

탐색기가 적용하는 규칙입니다.

- 버튼 바로 위에 표지판 블록이 있고 버튼 두 칸 아래에 floor 블록이나 base 블록이 있어야 승강기 버튼으로 인정합니다.
- 최하층은 버튼에서 수직으로 내려가며 찾습니다. 처음 만난 `baseBlocks` 재료가 base가 되고, 거기서 수평으로 이어진 같은 재료 블록들이 승강기 단면을 이룹니다.
- 위층은 그 단면의 모든 열을 따라 위로 올라가며 찾습니다. 어느 한 열이라도 유효한 버튼 구조를 갖춘 높이에 층이 생깁니다.
- 층 번호는 낮은 곳부터 `1`번으로 붙습니다. `1`층이 최하층입니다.
- 단면 열 안에 설정된 floor, button, sign, shaft 블록이 아닌 단단한 블록이 있으면 그 높이에서 탐색이 멈춥니다. 막힌 지점보다 위쪽은 승강기에 보이지 않습니다.
- 승강기에는 최소 두 개 층이 필요합니다. 한 층뿐이면 `oneFloor` 메시지로 안내합니다.

제어 표지판은 층 상태를 다음 순서로 고정 표기합니다.

```text
1번 줄   Current Floor: 3      messages.currentFloor + ": " + 현재 층 번호
2번 줄   Lobby                 현재 층 이름
3번 줄   Destination: 5        messages.destination + ": " + 목적지 층 번호
4번 줄   Roof                  목적지 층 이름
```

목적지 층 번호는 3번 줄의 마지막 `:` 뒤 문자열에서 읽으므로 `messages.currentFloor`와 `messages.destination` 문구는 자유롭게 번역해도 됩니다. 층 이름은 버튼 한 칸 아래의 선택적 벽 표지판에서 가져오고, 그 표지판이 없으면 제어 표지판 2번 줄을 씁니다.

첫 줄이 비어 있는 제어 표지판을 우클릭하면 승강로 안의 초기화되지 않은 표지판이 모두 채워지고 다른 동작은 하지 않습니다. 승강기에 필요한 설정 작업은 이것뿐입니다.

### 층 선택과 확정

같은 표지판에서 손에 든 물건에 따라 두 가지 방식이 동작합니다.

- **물건을 든 경우.** 제어 표지판을 우클릭할 때마다 목적지가 한 층씩 넘어가고 즉시 표지판에 기록됩니다. 확정 단계가 없습니다.
- **빈손이고 `mouseScroll: true`인 경우.** 우클릭하면 스크롤 선택이 시작됩니다. 핫바를 굴리면 한 칸에 한 층씩, 웅크린 채 굴리면 `selection.fastStep`만큼 이동합니다. 액션바에 층 번호, 층 이름, 전체 층 목록에서의 위치가 표시됩니다. `selection.preserveHotbar`가 켜져 있으면 실제 핫바 슬롯은 바뀌지 않습니다.

스크롤 선택은 손 바꾸기 키(`selection.confirmWithSwapKey`), 표지판 재우클릭, 승강기 버튼 누르기로 확정합니다. `selection.timeoutSeconds`초 동안 조작이 없거나, 표지판에서 3블록 넘게 멀어지거나, 월드를 옮기거나, 사망하거나, `lift.change` 권한을 잃거나, 접속을 끊거나, 설정을 다시 읽으면 자동으로 종료됩니다. 한 표지판은 동시에 한 명만 잡을 수 있고, 두 번째 사람에게는 `scrollSelectBusy` 메시지가 표시됩니다.

현재 층은 목적지 후보에서 제외되므로 승강기는 항상 어딘가로 이동합니다.

### 운행 중 동작

버튼을 누르면 표지판에 표시된 목적지로 운행이 시작됩니다.

- 승강로 단면 안에서 출발 층에 서 있는 대상이 모두 함께 이동합니다. `liftMobs`를 `false`로 두지 않는 한 몹과 탈것도 포함됩니다.
- 승강기가 지나가는 층에서 기다리는 대상은 해당 층 블록이 잠시 제거되는 동안 제자리에 고정되고 보호받습니다. 경로 밖 층은 전혀 건드리지 않습니다.
- 운행 중인 승강로와 겹치는 곳에서의 추가 호출은 운행이 끝날 때까지 `busy` 메시지로 거절됩니다. 움직이는 승강기의 버튼이나 표지판을 눌러도 같은 응답을 받습니다.
- 경로상의 floor 블록, 그 바로 위의 표지판이 아닌 블록, 함께 이동하는 마인카트 아래 레일은 운행 동안 제거되었다가 종료 시 복구됩니다.
- 중력, 무적, 비행 허용, 비행 상태는 출발 전에 저장하고 종료 후 되돌립니다.
- `preventLeave`가 켜져 있으면 운행 중 이탈이 막히고 탑승자는 승강로 중앙으로 되돌아갑니다. `preventEntry`를 `true`로 두면 다른 플레이어가 운행 중인 승강로로 걸어 들어올 수 없습니다.
- 운행 중 탈것에서 내리는 동작은 취소되고 `unsafe` 메시지가 표시됩니다.
- 예상 이동 시간을 `secondsUntilTimeout`초만큼 넘기면 탑승자를 목적지로 순간이동시키고 `timeout` 메시지로 알립니다.
- 운행 도중 접속을 끊으면 최하층 중앙으로 이동하며, 다음 접속 때 같은 안전 위치가 다시 적용됩니다.

### 마이그레이션 범위

코드와 런타임 검증으로 확인한 범위입니다.

- `plugin.yml`에 `provides: [Lift, LiftReloaded]`가 선언되어 있어 두 이름에 의존하는 플러그인이 그대로 해석됩니다.
- 첫 실행 시 `plugins/SimpleLift/config.yml`이 없으면 `plugins/LiftReloaded/config.yml`을, 없으면 `plugins/Lift/config.yml`을 복사하고 가져온 경로를 로그에 남깁니다. 둘 다 없으면 내장 기본 설정을 기록합니다.
- `baseBlocks`는 두 형식을 모두 읽습니다. 현재의 `type`/`speed`/`music` 목록과 재료를 키로 쓰는 버전 1 맵입니다.
- 명령어 이름, 별칭, 권한 노드, 표지판 줄 배치, 메시지 키, `*BUTTON` 같은 재료 글로브 문법이 그대로입니다.
- 기존 Lift/LiftReloaded 블록·표지판 배치를 사용하는 승강기는 구조 변환이 필요하지 않습니다.

이어받지 않은 것: NoteBlockAPI `.nbs` 재생은 구현되어 있지 않습니다. 기존 `music: true` 항목은 그대로 읽되 경고를 남기고, SimpleLift는 자체 이동 효과음을 사용합니다.

## 요구 사항

| 항목 | 요구 사항 |
|---|---|
| 서버 | Bukkit, Spigot, Paper, Purpur 계열, Minecraft 1.13부터 26.3 (`api-version: '1.13'`) |
| Java | 서버 버전이 요구하는 버전. JAR 자체는 Java 8 바이트코드라 별도 하한을 더하지 않습니다 |
| 다른 플러그인 | 없음. 런타임에 내려받는 것도 없습니다 |
| Folia | 미지원. Folia를 감지하면 스스로 비활성화합니다 |

Minecraft 1.12 이하에서는 `api-version: '1.13'`이 거부되어 플러그인이 아예 로드되지 않습니다.

## 설치

1. 서버를 종료하고 월드와 `plugins` 폴더를 백업합니다.
2. 기존 Lift 또는 LiftReloaded JAR이 있으면 제거합니다. SimpleLift와 함께 실행하지 마십시오.
3. `SimpleLift-0.3.3-SNAPSHOT.jar`를 `plugins`에 넣습니다.
4. 서버를 정상적으로 시작하고 콘솔을 확인합니다. `SimpleLift <버전> enabled on <서버 버전>`이 기록되며, 기존 설정을 가져왔다면 그 경로도 함께 남습니다.
5. `/lift info`를 실행하고 기존 승강기를 타 봅니다.

플러그인 관리자를 통한 재로드 대신 서버를 완전히 재시작하십시오. 설정 변경에는 `/lift reload`만 지원합니다.

## 5분 빠른 시작

기본 설정으로 2층 승강기를 만드는 과정입니다.

1. 땅에 `IRON_BLOCK`을 놓습니다. 이것이 base 블록이자 한 열짜리 승강기의 단면 전체입니다.
2. 그 두 칸 위, 옆 벽에 버튼을 답니다. 버튼 한 칸 위에 벽 표지판을 답니다. 버튼은 base 높이 +2, 표지판은 +3입니다.
3. 다섯 칸 이상 위에 위층을 만듭니다. base 블록과 같은 열에 `GLASS`를 놓고, 같은 방식으로 +2에 버튼, +3에 표지판을 답니다.
4. 두 층 사이 열은 비워 둡니다. 공기, 사다리, 횃불, 덩굴, 물, 레일, 눈, 레드스톤 가루는 허용되고 그 밖의 단단한 블록은 탐색을 멈춥니다.
5. 아무 제어 표지판이나 한 번 우클릭합니다. 두 표지판에 현재 층과 목적지가 채워집니다.
6. 아래층 floor 블록 위에 서서 버튼을 누르고 올라갑니다. 위층에서 버튼을 누르면 내려옵니다.

승강기를 넓히려면 처음 놓은 블록 옆에 `IRON_BLOCK`을 더 놓고, 그중 아무 열에나 floor 블록·버튼·표지판을 똑같이 만들면 됩니다. 단면은 `maxLiftArea`까지 넓힐 수 있으며 기본값은 49입니다.

## 기본 사용법

- **원하는 층으로 보내기:** 목적지 줄에 원하는 층이 나올 때까지 제어 표지판을 우클릭한 뒤 버튼을 누릅니다.
- **스크롤로 층 고르기:** 빈손으로 표지판을 우클릭하고 원하는 층까지 굴린 뒤, 손 바꾸기 키나 버튼으로 확정합니다.
- **여러 층 건너뛰기:** 웅크린 채 굴리면 한 칸에 `selection.fastStep`층씩 이동합니다.
- **함께 타기:** 단면 안에서 출발 층에 서 있는 사람은 모두 같이 이동합니다.
- **층 이름 붙이기:** 버튼 한 칸 아래에 벽 표지판을 달고 두 번째 줄에 이름을 적습니다.
- **레드스톤으로 호출하기:** `redstone: true`로 설정합니다. 승강기 버튼이나 그 지지 블록에 전원이 들어오는 순간 운행이 시작되며, 그때 해당 층에 있던 대상만 태웁니다.

탑승에는 `lift` 권한이, 표지판의 목적지 변경에는 `lift.change` 권한이 필요합니다.

## 명령어와 권한

| 명령어 | 동작 | 권한 |
|---|---|---|
| `/lift` 또는 `/lift info` | 플러그인 버전과 지원 범위를 출력 | `lift` |
| `/lift reload` | `config.yml`을 검증하고 다시 읽음 | `lift.reload` |

`/simplelift`는 `/lift`의 별칭입니다. 두 하위 명령 모두 탭 완성을 지원하며 `reload`는 `lift.reload` 권한이 있는 사용자에게만 제안됩니다.

| 권한 | 허용 범위 | 기본값 |
|---|---|---|
| `lift` | 승강기 탑승과 기본 명령 사용 | 모두 |
| `lift.change` | 제어 표지판의 목적지 변경 | 모두 |
| `lift.reload` | 설정 다시 읽기 | 운영자 |

`/lift reload`는 서버를 망가진 상태로 두지 않습니다. 새 파일이 검증을 통과하지 못하면 실행자에게 오류를 알리고 로그에 남긴 뒤 이전 설정을 그대로 유지합니다. 재로드에 성공하면 열려 있던 층 선택이 모두 종료되고, 이미 진행 중인 운행은 시작할 때의 설정으로 끝까지 진행됩니다.

## 설정

설정 파일은 `plugins/SimpleLift/config.yml` 하나뿐입니다. 파일에 없는 값은 내장 기본값으로 채워집니다.

| 키 | 용도 | 허용 범위 |
|---|---|---|
| `maxLiftArea` | 한 단면에 연결될 수 있는 base 블록 최대 개수 | 1–4096, 기본 49 |
| `minHeight`, `maxHeight` | 수직 탐색 범위. 월드 자체 건축 한계로 한 번 더 제한됨 | `maxHeight`가 `minHeight`보다 커야 함 |
| `baseBlocks` | 최하층 재료와 `speed`, 그리고 기존 `music` 플래그 | `speed`는 0 초과 10 이하, 재료 중복 불가 |
| `floorBlocks`, `buttonBlocks`, `signBlocks`, `shaftBlocks` | 재료 이름 또는 `*WALL_SIGN` 같은 `*` 글로브 | 앞의 세 개는 각각 실제 블록 재료를 하나 이상 매치해야 함 |
| `mouseScroll` | 빈손 스크롤 선택 사용 | boolean |
| `selection.preserveHotbar` | 스크롤 중 실제 슬롯 유지 | boolean |
| `selection.actionBar` | 선택 상태를 액션바에 표시 | boolean |
| `selection.timeoutSeconds` | 선택 무조작 제한 시간. `0`이면 만료 없음 | 0–300, 기본 8 |
| `selection.fastStep` | 웅크린 스크롤 한 칸당 이동 층 수 | 1–20, 기본 5 |
| `selection.confirmWithSwapKey` | 손 바꾸기 키로 확정 허용 | boolean |
| `secondsUntilTimeout` | 강제 종료 전 예상 이동 시간에 더하는 여유 시간 | 0–60, 기본 2 |
| `preventEntry`, `preventLeave` | 운행 중 승강로 진입·이탈 차단 | boolean |
| `liftMobs` | 플레이어가 아닌 엔티티 탑승 | boolean |
| `autoPlace` | 출발 전 탑승자를 층 중앙으로 정렬 | boolean |
| `redstone` | 레드스톤 신호로 호출 허용 | boolean |
| `soundEnabled`, `soundVolume` | 이동·도착 효과음 | 음량 0–100 |
| `debug` | 탐색·운행 상세 로깅 | boolean |
| `messages.*` | 모든 사용자 문구, `&` 색상 코드 사용 | 문자열 |

`messages.scrollSelection`, `messages.scrollSelectConfirmed` 등 선택 관련 메시지에서는 `{floor}`, `{name}`, `{index}`, `{total}`이 치환됩니다.

허용 범위를 벗어난 값, 알 수 없는 재료 이름, 잘못된 글로브 패턴은 해당 키를 명시한 메시지와 함께 거부됩니다. 시작 시점의 설정 오류는 플러그인을 비활성화시키고, `/lift reload` 중의 오류는 실행 중인 설정을 건드리지 않습니다.

### 언어와 스크린샷 촬영

`language`에 아래 내장 로케일을 지정하거나, `language: custom`으로 기존
`messages` 문구를 어떤 언어로든 직접 작성할 수 있습니다. 기본값은 `custom`으로
기존 번역 설정을 유지합니다. 내장 로케일은 `messages` 전체보다 우선하며,
custom에서 빠진 문구만 내장 영어 기본값을 사용합니다.

| 언어 | `language` 값 |
|---|---|
| 영어(미국), 영어(영국) | `en` (`en_US`), `en_GB` |
| 불가리아어, 체코어, 덴마크어, 독일어, 그리스어 | `bg`, `cs`, `da`, `de`, `el` |
| 스페인어, 에스토니아어, 핀란드어, 프랑스어, 헝가리어 | `es`, `et`, `fi`, `fr`, `hu` |
| 이탈리아어, 일본어, 한국어, 리투아니아어, 네덜란드어, 노르웨이어 | `it`, `ja`, `ko`, `lt`, `nl`, `no` |
| 폴란드어, 포르투갈어(포르투갈), 포르투갈어(브라질), 루마니아어 | `pl`, `pt` (`pt_PT`), `pt_BR`, `ro` |
| 러시아어, 스웨덴어, 터키어, 우크라이나어, 베트남어 | `ru`, `sv`, `tr`, `uk`, `vi` |
| 중국어(간체), 중국어(홍콩), 중국어(번체) | `zh` (`zh_CN`), `zh_HK`, `zh_TW` |

로케일 값은 대소문자를 구분하지 않으며 `_`와 `-`를 모두 쓸 수 있습니다. 예를
들어 `pt-BR`, `ja_JP`, `zh-Hant`, `zh-MO`가 동작합니다. 이는 플레이어별 클라이언트
언어가 아니라 서버 전체에 적용되는 설정입니다.

영어 스크린샷을 촬영하려면 새 빌드 적용 후 `plugins/SimpleLift/config.yml`에
`language: en`을 추가하고 `/lift reload`를 실행하십시오. 각 승강기를 조작하면
현재 층·목적지 표지판 문구도 갱신됩니다. 선택했던 목적지와 직접 작성한 층 이름은
유지됩니다. 영어 층 이름이 필요하면 Lobby, Roof 등으로 직접 바꾸십시오.
일반 안내·액션바·표지판 제목·정보 명령·재로드 응답에 적용되고,
기술 진단의 상세 내용은 영어로 남을 수 있습니다.

### 버튼별 도착 알림음

나무 버튼에는 낮은 2음 종소리 `warm`, 돌 버튼에는 맑은 3음 차임 `crystal`이
배정됩니다. 나머지 재료는 기존 종소리 `legacy`를 사용합니다.
밝은 2음 종소리 `clear`도 선택할 수 있으며 `silent`는 도착음을 끕니다.
기존 설정에서 명시적으로 지정한 프로필은 그대로 유지됩니다.

0.3.2부터 warm과 clear는 높은 음에서 낮은 음으로 내려가는 띵동 패턴이며,
간격은 8틱(20 TPS에서 0.4초)입니다. 두 음 모두 기존 legacy와 같은 음량
계수를 사용하고 crystal의 음량도 높였습니다. 전체 음량은 `soundVolume`으로
조절하며 이동음과 버튼 클릭음은 바뀌지 않습니다. 기본 악기로 종소리를
표현한 것으로, 실제 엘리베이터의 녹음 음원은 아닙니다.

0.3.3에서 추가된 선택형 프로필 `hotel`은 낮은 차임 음색으로 장3화음을 내려가는 세 음짜리 알림입니다.
0·5·12틱(20 TPS에서 0·0.25·0.6초)에 재생하며, 마지막 음 앞의 간격을
조금 늘려 여유 있게 마무리합니다. 두 번째와 세 번째 음량은 첫 음의 90%입니다.

```yaml
arrivalChimes:
  default: legacy
  tags:
    "minecraft:wooden_buttons": warm
    "minecraft:stone_buttons": crystal
  materials:
    OAK_BUTTON: hotel
    STONE_BUTTON: legacy
```

재질별 지정이 그룹보다 우선합니다. 그룹 우선순위는 `minecraft:wooden_buttons`,
`minecraft:stone_buttons`, `minecraft:buttons` 순서이며 일치하지 않으면
`default`를 씁니다. 이 세 가지 마인크래프트 표준 블록 태그만 지원합니다.
구성원은 설정을 읽을 때 서버 태그에서 가져오므로 데이터 팩 변경도 반영됩니다.
`stone_buttons`가 없는 구버전에서는 알려진 돌 버튼 재질을 대신 판별합니다.
재질별 지정에는 해당 서버에 존재하고 `buttonBlocks`에 포함된 재료를 쓰십시오.
위 예에서는 참나무 버튼만 `hotel`을 쓰고 나머지 나무 버튼은 `warm`을 씁니다.
이 지정은 블록 종류별이며 월드 좌표별 지정은 지원하지 않습니다.
그룹과 재질 지정이 겹쳐도 유효하며, 같은 `materials` 맵 안에 동일 재질 키를
두 번 작성하지 마십시오.

`tags`를 생략하면 내장 나무·돌 배정을 받습니다. 직접 작성한 맵은 내장 배정을
대체하며, `tags: {}`는 그룹 배정을 모두 끕니다. 수정 후 `/lift reload`를
실행하십시오. 잘못된 음색·태그·재질이 있으면 이전 설정을 유지합니다.
기존 설정 파일은 덮어쓰지 않고 메모리에서 누락된 기본값을 채웁니다.

레드스톤 호출을 포함해 운행을 시작한 버튼의 재질로 음색을 정합니다.
운행 중에는 그 음색과 음량이 유지됩니다. 운행 완료 시 탑승자와 경로상에서
보호받던 대기자에게 각각 한 번씩 들립니다. 동시 운행은 각 설정을 유지하며,
같은 플레이어에게 새 알림음이 시작되면 이전 음의 남은 부분을 취소합니다.
로그아웃·플러그인 종료·설정 재로드 성공 시 예약된 음을 취소합니다.
기존 `soundEnabled`와 `soundVolume` 설정도 적용됩니다.

SimpleLift용으로 직접 구성한 짧은 음형을 Minecraft 내장 노트 블록 악기로
재생합니다. 녹음·게임 음원 추출물·음원 다운로드·리소스팩을 배포하지 않습니다.
음형은 프로젝트의 GPL-3.0 소스에 포함되고 게임 음원은 클라이언트가 제공합니다.
클릭음과 이동음은 기존과 같습니다. 새 음색의 게임 내 청음은 아직 필요하며,
아래 런타임 검증 표는 이전 빌드의 결과입니다.

### 저장, 네트워크, 클라이언트 동작

의도가 아니라 소스에서 확인한 사실입니다.

- **기록하는 파일:** `plugins/SimpleLift/config.yml` 하나뿐이며, 첫 실행 시 기존 설정을 가져오거나 내장 기본값으로 생성합니다. 그 밖에 디스크에 쓰는 것은 없습니다.
- **승강기 영구 데이터:** 없습니다. 승강기 목록, 플레이어 데이터 파일, 캐시가 없습니다. 승강기 구조는 조작할 때마다 월드 블록에서 다시 읽으며, 유일하게 남는 상태는 월드 세이브에 저장되는 표지판 문구입니다.
- **데이터베이스:** 로컬·원격 모두 사용하지 않습니다. JDBC, SQLite, MySQL 코드가 없고 관련 설정도 없습니다.
- **네트워크:** 사용하지 않습니다. HTTP, 소켓, `java.net` 사용이 없고 업데이트 확인이나 통계·텔레메트리 전송도 없습니다. `build.gradle.kts`의 Maven 저장소는 소스를 빌드할 때만 쓰입니다.
- **의존성 자동 다운로드:** 없습니다. 서버 API는 컴파일 전용 의존성이며 런타임에 내려받는 것이 없습니다.
- **클라이언트 소프트웨어:** 필요 없습니다. 리소스 팩, 모드, 플러그인 메시지 채널을 쓰지 않습니다. 액션바, 채팅, 효과음 모두 표준 서버 API를 사용하며 액션바 전송이 실패해도 운행에 영향을 주지 않고 무시됩니다.
- **스레드:** 모든 탐색과 운행 처리는 서버 스레드에서 실행되며, 메인 스레드 밖에서 시도한 탐색은 즉시 거부됩니다.

## 업그레이드

**Lift 또는 LiftReloaded에서 옮길 때.** 위 설치 절차를 따릅니다. 첫 실행에서 기존 `config.yml`을 `plugins/SimpleLift/config.yml`로 가져옵니다. 보존된 블록·표지판 배치를 사용하는 승강기는 구조 변환이 필요하지 않습니다. 예전 플러그인 폴더는 그대로 두어도 되며, SimpleLift가 자체 설정 파일을 갖춘 뒤에는 다시 읽지 않습니다.

**이전 SimpleLift 빌드에서 올릴 때.** 서버를 종료하고 JAR을 교체한 뒤 다시 시작합니다. 새 릴리스에서 추가된 키는 내장 기본값으로 채워지므로 예전 `config.yml`도 그대로 로드됩니다. 값을 바꾸고 싶을 때 기본 설정에서 해당 키를 복사해 오면 됩니다.

**설정 수정.** `plugins/SimpleLift/config.yml`을 수정한 뒤 `/lift reload`를 실행합니다. 콘솔을 확인하십시오. 검증에 실패하면 이전 설정이 유지되므로, 오류가 보고된 재로드는 수정이 반영되지 않은 상태입니다.

운영에 적용하기 전에 별도 사본에서 [수동 인수 테스트](docs/manual-acceptance.ko.md)를 완료하십시오.

## 호환성과 제한 사항

[호환성 보고서](docs/compatibility.ko.md)에 기록된 런타임 검증 결과입니다.

| 서버 | Java | 결과 |
|---|---|---|
| Paper 1.13.2 빌드 657 | Temurin 11.0.32 | 런타임 시나리오 38/38 |
| Paper 1.16.5 빌드 794 | Temurin 17.0.17, 시험용 버전 검사 우회 | 런타임 시나리오 38/38 |
| Paper 1.20.6 빌드 151 | Temurin 21.0.9 | 런타임 시나리오 38/38 |
| Paper 1.21.8 빌드 60 | Temurin 21.0.9 | 런타임 시나리오 38/38 |
| Paper 26.2 빌드 112 | Temurin 25.0.4 | 런타임 시나리오 38/38 |

0.3.1-SNAPSHOT은 JDK 21의 Spigot `1.13.2-R0.1-SNAPSHOT` API와 JDK 25의
Paper `26.2.build.112-stable` API로 각각 Java 8 바이트코드를 대상으로 빌드했고,
두 구성 모두 단위 테스트 42개 중 42개가 통과했습니다. 위 런타임 표는
0.3.0-SNAPSHOT 기록이며 새 도착음의 게임 내 검증 결과는 아닙니다.

선택형 hotel 도착음을 포함한 0.3.3-SNAPSHOT은 Spigot 1.13.2 API를 대상으로
클린 빌드해 단위 테스트 47개 중 47개가 통과했습니다. JDK 25에서 Paper
`26.3.build.218-stable` API로 별도 클린 빌드한 결과도 47개 모두 통과했습니다.
기존 `0.3.3-26.3-beta.2` JAR이 Paper 26.3 빌드 157에서 정상 활성화된 기록을
확인했습니다. 이 JAR의 실행 클래스와 리소스는 게시된 0.3.3-SNAPSHOT과 같고
버전 메타데이터만 다릅니다. 이는 시작 확인이며 전체 운행 시나리오나 클라이언트
음향 검증을 뜻하지 않습니다. 게임 내 청음 확인은 남아 있습니다.

지원 대상으로 삼지만 개별 런타임 검증은 하지 않은 범위는 1.13부터 26.3까지의 나머지 Minecraft 릴리스와 Bukkit, Spigot, Purpur 계열 서버입니다. 배포 JAR은 1.13.2 API로 컴파일하고 NMS나 서버 내부 클래스를 쓰지 않으며, 버전 사이에 달라진 소수의 API(`World#getMinHeight`, 플러그인 청크 티켓, 청크 언로드 취소)는 리플렉션으로 접근합니다. 검증하지 않은 버전은 확인된 것이 아니라 동작이 예상되는 범위로 보십시오.

알려진 제한 사항입니다.

- **Folia는 지원하지 않습니다.** 움직이는 승강기가 리전 소유 경계를 넘을 수 있는데 리전 스케줄링이 구현되어 있지 않습니다. 활성화 시 Folia를 감지하면 사유를 로그로 남기고 스스로 비활성화합니다.
- **Minecraft 1.12 이하에서는 플러그인이 로드되지 않습니다.**
- **핫 리로드는 지원하지 않습니다.** 서버 완전 재시작이나 `/lift reload`를 사용하십시오. 운행 중에 플러그인 관리자로 언로드하거나 교체하는 경우는 검증하지 않았으며, 제거된 floor 블록은 플러그인 자체 종료 경로에서만 복구됩니다.
- **강제 종료 시 임시 블록이 남을 수 있습니다.** 정상 종료에서는 제거된 floor 블록과 변경된 엔티티 속성이 모두 복구되지만, 운행 도중의 강제 종료 신호나 크래시, 정전에서는 보장할 수 없습니다.
- **NoteBlockAPI 음악은 구현되어 있지 않습니다.** `music: true`는 읽되 경고를 남깁니다.
- **탐색 범위에 상한이 있습니다.** `maxLiftArea`를 넘는 단면은 거부되며, 탐색 비용은 단면 넓이와 승강로 높이에 따라 커집니다. 7 × 7 단면에 Y −60부터 316까지 95개 층을 둔 구성이 정상 동작했고, 속도 `1.0`에서 376블록 상승에 19.4초가 걸렸으며 임시 블록 4,606개가 복구되었습니다.
- **실제 클라이언트 확인은 수동으로 남아 있습니다.** 입력 처리, 권한, 재접속 동작, 화면 표시는 자동 테스트가 아니라 수동 점검 목록으로 확인합니다.

## 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| 플러그인이 활성화되지 않고 콘솔에 Folia가 언급됨 | Folia는 미지원입니다. Paper, Spigot, Bukkit, Purpur를 사용하십시오. |
| 플러그인이 활성화되지 않고 콘솔에 설정 오류가 표시됨 | 메시지에 문제 키가 적혀 있습니다. `plugins/SimpleLift/config.yml`을 고치고 재시작하십시오. |
| `There is only one floor.` | 층이 두 개 미만으로 탐지되었습니다. 위층에 base 열과 같은 열의 floor 블록, 그 두 칸 위 버튼, 버튼 위 표지판이 있는지, 목록에 없는 단단한 블록이 승강로를 막고 있지 않은지 확인하십시오. |
| `Floor does not exist. Check shaft for blockage` | 표지판의 목적지가 현재 층으로 되돌아왔습니다. 대개 그 너머 층이 장애물로 끊긴 경우입니다. |
| `Lift footprint exceeds maxLiftArea (N).` | 연결된 base 블록이 `maxLiftArea`를 넘었습니다. 단면을 줄이거나 값을 최대 4096까지 올리십시오. |
| 버튼을 눌러도 아무 일도 없음 | 단면 안 해당 층에 태울 대상이 없었습니다. floor 블록 위에 서십시오. 몹이나 탈것을 태우려면 `liftMobs`를 확인하십시오. |
| `This lift is already moving.` | 다른 운행이 이 승강로와 겹칩니다. 끝날 때까지 기다리십시오. |
| `Another player is selecting a floor on this sign.` | 다른 사람이 그 표지판의 선택을 잡고 있습니다. |
| 스크롤해도 반응이 없음 | `mouseScroll`이 꺼져 있거나, `lift.change` 권한이 없거나, 표지판에서 3블록 넘게 떨어졌거나, 선택이 이미 종료된 상태입니다. |
| 선택이 저절로 사라짐 | `selection.timeoutSeconds`가 지났거나, 자리를 옮겼거나 월드를 이동했거나, 설정을 다시 읽었습니다. `selection.timeoutSeconds: 0`으로 두면 만료가 없어집니다. |
| `Can't leave elevator in use` / `Can't enter elevator in use` | `preventLeave`와 `preventEntry`가 동작한 것입니다. 원하지 않으면 끄십시오. |
| `It is unsafe to leave a vehicle in a lift!` | 운행 중 탈것에서 내리는 동작은 막힙니다. 도착을 기다리십시오. |
| `You have been teleported to the destination due to timeout` | 예상 이동 시간에 `secondsUntilTimeout`을 더한 시간을 넘겼습니다. 승강로 장애물을 확인하거나 `secondsUntilTimeout`을 늘리십시오. |
| 표지판 줄이 이상하거나 목적지가 유지되지 않음 | 제어 표지판을 부수고 다시 설치한 뒤, 비어 있는 상태에서 한 번 우클릭해 승강로를 다시 초기화하십시오. |

원인을 찾기 어려울 때는 `debug: true`로 두고 다시 읽으면 탐색과 운행 단위의 로그를 볼 수 있습니다.

## 지원

문제를 알릴 때는 서버 소프트웨어와 빌드 번호, Java 버전, `plugins/SimpleLift/config.yml` 전체, `debug: true` 상태의 관련 콘솔 출력, 승강기 구조 설명이나 스크린샷을 함께 전달하십시오. 배포 전에 통과해야 하는 점검 항목은 [호환성 보고서](docs/compatibility.ko.md)와 [수동 인수 테스트](docs/manual-acceptance.ko.md)에 정리되어 있습니다.

재현 가능한 버그와 호환성 보고는 [GitHub 이슈 트래커](https://github.com/tdbgo/simplelift-minecraft-plugin/issues)에 남겨 주십시오.

## 소스에서 빌드

최저 지원 API 기준 빌드와 테스트:

```powershell
.\gradlew.bat clean build --console=plain
```

JDK 25에서 Paper 26.3 API로 교차 컴파일과 테스트:

```powershell
.\gradlew.bat clean test --console=plain `
  '-PapiGroup=io.papermc.paper' `
  '-PapiArtifact=paper-api' `
  '-PapiVersion=26.3.build.218-stable' `
  '-PjavaToolchainVersion=25' `
  '-PjavaRelease=8'
```

빌드 결과로 `SimpleLift-0.3.3-SNAPSHOT.jar`와 소스 JAR이 생성됩니다.
